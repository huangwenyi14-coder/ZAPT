# Graph Schema v0.1.0

## Nodes

Every line in `nodes.jsonl` is one entity:

```json
{
  "schema_version": "0.1.0",
  "id": "uuid",
  "type": "SUBJECT",
  "host": "WS-VICTIM-01",
  "natural_key": "WS-VICTIM-01:source-uuid",
  "first_seen_ns": 1732615200000000000,
  "last_seen_ns": 1732615300000000000,
  "properties": {}
}
```

Supported node types and their CDM analogues:

| Node type | CDM analogue | Typical source |
|---|---|---|
| `SUBJECT` | Subject | Process UUID |
| `FILE_OBJECT` | FileObject | File/module UUID |
| `NET_FLOW_OBJECT` | NetFlowObject | Canonical connection UUID |
| `REGISTRY_KEY_OBJECT` | RegistryKeyObject | Registry event UUID |
| `PRINCIPAL` | Principal | User/service identity |
| `HOST` | Host | eCAR hostname |
| `SESSION` | Object extension | Login/session UUID |
| `THREAD` | Subject/Object extension | Remote-thread UUID |

Native UUIDs are preserved. Entities without a native UUID use deterministic UUIDv5
identifiers. A process UUID can be resolved from `actorID` directly or, when absent,
from the active host/PID lifetime.

## Edges

Every line in `edges.jsonl` represents one eCAR source record. No event is silently
expanded into several graph edges.

```json
{
  "schema_version": "0.1.0",
  "id": "event-uuid",
  "sequence": 42,
  "timestamp_ns": 1732615250000000000,
  "type": "EVENT_READ",
  "subject_id": "process-uuid",
  "object_id": "file-uuid",
  "causal_from": "file-uuid",
  "causal_to": "process-uuid",
  "host": "WS-VICTIM-01",
  "properties": {},
  "source": {
    "format": "ecar",
    "relative_path": "WS-VICTIM-01.example.local/ecar.json",
    "record_index": 42,
    "source_instance": "WS-VICTIM-01.example.local"
  }
}
```

`subject_id` and `object_id` preserve source event roles. `causal_from` and
`causal_to` make information-flow direction explicit:

| Event | Causal direction |
|---|---|
| Process create | parent process → child process |
| File read / module load | file → process |
| File create / write / delete | process → file |
| Outbound connect | process/host → flow |
| Inbound connect | flow → process/host |
| Process open / remote thread | source process → target process |
| Login | principal → session |

Process exit is a unary event and therefore has no `object_id` or `causal_to` in
the neutral graph. The SPADE adapter emits it as an annotated self-edge because
SPADE requires two endpoints.

## Offline labels

`labels.jsonl` joins an edge UUID to record-level provenance generated by
EvidenceForge. It includes storyline IDs, logical event IDs, detectability class,
and causal parentage. This file is deliberately excluded from `spade.jsonl`,
`nodes.jsonl`, and `edges.jsonl`.
